# Задача: один набор английских скриншотов в документации сайта

> Стартовый промпт для нового агентского таба. Скопируй в новый чат.
> Репозиторий: `gitbor-web` (рядом с `gitbor`).

---

## Проблема

В `gitbor-web` структура скриншотов закладывалась под локализацию: `public/screenshots/en/`, `public/screenshots/ru/`. Идея — для каждого языка свой набор изображений с переведёнными подписями кнопок.

Это масштабируется плохо. Языков планируется больше двух, автор многие из них не знает — проверять корректность переводов в UI и переснимать одни и те же экраны N раз не получится. Скриншотов пока **ноль реальных файлов** (только `.gitkeep`), момент для смены концепции идеальный — ничего переснимать не надо.

## Решение

Один набор скриншотов — **только английский**. В тексте MDX рядом с упоминанием UI-элемента приводим английскую подпись (как в скрине) и в скобках перевод для текущего языка документа.

Пример (русский MDX):
> Нажмите **Open Repository** («Открыть репозиторий») или используйте `Ctrl+O`.

Пример (английский MDX):
> Click **Open Repository** or press `Ctrl+O`.

Для языков, где это не очевидно (китайский, арабский) — тот же паттерн: английская подпись остаётся как ключ узнавания на скрине, перевод в скобках.

## Что сделать

### 1. Структура файлов

- Удалить `public/screenshots/ru/` и любые языковые подпапки.
- Скриншоты класть в `public/screenshots/` плоско или сгруппированно по разделу: `public/screenshots/getting-started/toolbar.png`, `public/screenshots/diff/side-by-side.png` и т.п.
- Имя файла — английское, описательное, kebab-case.

### 2. Компонент `<Screenshot />`

Файл `src/shared/ui/screenshot.tsx`. Сейчас принимает `file`-проп с language-prefix (`"en/toolbar.png"`).

Меняем:
- проп `file` ожидает путь от `/screenshots/` без language-сегмента: `file="getting-started/toolbar.png"`.
- проп `caption` — на языке текущего документа (это не меняется).
- никакой логики выбора per-locale внутри компонента — один путь для всех.

### 3. MDX-документация

Во всех `src/content/docs/{en,ru,...}/*.mdx`:
- обновить `file="..."` пути (убрать `en/` / `ru/` префиксы);
- в текстах рядом со скриншотами привести английские подписи + перевод в скобках там, где смысл не очевиден (для en-документа перевод не нужен).

Шаблон для не-английских версий:
```mdx
В тулбаре есть кнопка **Fetch** («Получить»), которая запускает `git fetch`.
```

### 4. Документация для контрибьюторов

В `gitbor-web/docs/CLIENT-INTEGRATION.md` (или новый раздел) описать конвенцию:
- скриншоты только английские;
- английский UI в GitBor поднимается принудительно: `LANG=en npm run dev` (или установка `--lang=en` в конфиге для электрон-сборки);
- разрешение скриншотов: фикс (например, 1440×900 или 1600×1000) — описать в стайлгайде, чтобы пропорции были одинаковы.

### 5. Проверка ссылок

Скрипт (можно одноразовый) который пройдёт по всем MDX и проверит что каждый `file="..."` указывает на существующий файл в `public/screenshots/`. Сейчас они все ведут в никуда, но когда появятся — сломанные ссылки ловить автоматически.

## Не делать

- Не вводить i18n-overlay поверх скриншотов (наложение переведённых tooltip'ов через CSS) — это дороже чем решение «в скобках».
- Не делать SVG-аннотации с переводами поверх PNG — опять слишком дорого.
- Не переснимать UI на каждом языке — это вся суть отказа от старой концепции.

## Риски

- В странах с RTL (арабский, иврит) английский UI смотрится чужеродно — оставляем как есть, это документация продукта на английском UI, не приложение.
- Скриншоты быстро устаревают при изменениях UI. Митигация: пометить в плане ревизий, после каждого UI-PR проверять не сломались ли подписи в документации (механически — поиском по `caption=` упоминаний кнопки).

## Запуск

Реализуй задачу из `docs/tasks/docs-screenshots-english-only.md` в репо `gitbor-web`. Без лишних вопросов.

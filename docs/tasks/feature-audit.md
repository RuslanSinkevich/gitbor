# GitBor — аудит фич и разгрузка продукта

> Документ для следующего стрима. Разговор ИИ ↔ человек, без воды и лести.
> Решения за тобой — я даю честную оценку и варианты.

---

## 0. Критерий оценки (важно)

Один вопрос к каждой фиче: **нужна ли она миддлу/синьору в реальной работе в GUI-клиенте, минимум раз в неделю?** Джуниор — не критерий (твоя установка).

Три вердикта:
- **KEEP** — ядро, на виду, трогать нельзя.
- **DEMOTE** — нужная, но редкая → убрать в подменю «Ещё / Advanced», не висеть в первом уровне.
- **CUT** — балласт. Убрать совсем или спрятать за флаг «экспериментальное».

Отдельно: **PASSIVE-KEEP** — фича ничего не стоит в меню (работает в фоне / в контекстном меню), оставляем не глядя.

Честный диагноз сверху: продукт раздут. Меню **Repository — 17 пунктов** в один уровень. Куча фич добавлена по принципу «чтобы было как у Fork/GitKraken», а не «этим пользуются». Это разбавляет фокус, грузит бандл и пугает нового человека.

## 1. Сначала чинить — 3 UX-косяка (корни найдены)

Это не про «добавить фич», а про «сделать понятно человеку». Делать в первую очередь.

### 1.1 Двойной клик по remote-ветке делает «хрен пойми что»
- **Сейчас:** `BranchTreeItem.onDoubleClick` → `requestCheckout('origin/foo')` → git checkout удалённой ветки → **detached HEAD**. Человек ждёт «забрать ветку к себе», а получает оторванную голову.
- **Надо (как ты сказал):** двойной клик по remote-ветке = **Track** — та же модалка, что уже есть в ПКМ (Задача 4): создать локальную ветку с tracking, checkout на неё, фокус в графе.
- **Где:** `BranchTreeItem` — развести `onDoubleClick` по `branch.isRemote`: remote → открыть Track-диалог; local → checkout как сейчас.
- **Цена:** маленькая. **Приоритет: высокий** (бесит каждый день).

### 1.2 Задача 5 — восстановление активного таба (по-настоящему НЕ починено)
- **Прошлый фикс лечил симптом** (debounce на восстановление). Реальный корень глубже:
  - Эффект сохранения: `useEffect(() => saveLastActiveRepo(state.repoPath), [state.repoPath])` пишет `sg-last-active-repo` на **каждую** смену активного репо.
  - При старте табы открываются асинхронно по одному, и каждый открытый репо на миг становится активным → `state.repoPath` меняется N раз → `sg-last-active-repo` **перезатирается последним загруженным**.
  - Мой debounce потом читает `loadLastActiveRepo()` — а там уже не то, что было при выходе, а последний прогрузившийся. Итог: «не тот / первый».
- **Корневой фикс:**
  1. Считать `loadLastActiveRepo()` **один раз** в `ref` при маунте (до начала восстановления).
  2. **Не вызывать** `saveLastActiveRepo` пока идёт восстановление (флаг `restorationDone`).
  3. Восстанавливать активный таб по значению из ref; только после этого включать сохранение.
- **Приоритет: высокий** (ты дважды на это указал).

### 1.3 Кэш/мемоизация фокуса в графе при повторном клике
- **Сейчас:** крутишь граф, кликаешь по той же ветке/коммиту повторно — реакции нет.
- **Корень (двойной):**
  - `selectCommit(hash)` при том же `hash` → setState тем же значением → React бейлит, ре-рендера нет.
  - Даже если бы был: эффект скролла в `CommitGraph` скроллит только при `selectedHash !== prevSelectedRef.current`. Тот же hash → скролла нет.
- **Фикс:** отдельный «scroll request» — счётчик-nonce, который инкрементится на **каждый** клик по ветке/строке (независимо от равенства hash) и триггерит `scrollToRow`. Выбор (подсветку) не трогаем, чиним только «доскролль к выбранному».
- **Приоритет: средний** (раздражает, но не ломает данные).

## 2. Аудит фич по тирам

### Tier 1 — Ядро (KEEP, на виду)
Ежедневный цикл миддла/синьора. Трогать нельзя.

| Фича | Кто и зачем |
|------|-------------|
| Commit graph + поиск (Ctrl+F) | смотреть историю — каждый день |
| Сайдбар веток/тегов/стэшей: checkout, merge, rename, delete, new | основной навигатор |
| Local changes: stage/unstage/discard (файл/ханк/папка) | каждый коммит |
| Diff (inline/split, ignore ws, hunk-actions) | каждый коммит |
| Commit bar + amend | каждый коммит |
| Тулбар Fetch / Pull / Push / Stash / Stash Pop | каждый день |
| Разрешение конфликтов (2-колоночный редактор) | регулярно |
| Multi-repo табы | у кого >1 репо — постоянно |
| История файла + Blame | расследования — регулярно |
| Cherry-pick / Revert (ПКМ коммита) | регулярно |
| Сравнить два коммита | регулярно |
| Track remote branch | забрать чужую ветку — регулярно (после фикса 1.1) |
| Remotes: add/remove/rename/fetch | настройка — периодически |
| **AI commit message** | единственная AI-фича с реальной пользой для миддла |
| Repository settings + **credentials (HTTPS пароль/PAT)** | смена корп. пароля — критично |

### Tier 2 — Продвинутое (DEMOTE в подменю «Repository → Ещё»)
Нужно, но редко. Не должно висеть в первом уровне меню рядом с Pull/Push.

| Фича | Вердикт | Почему |
|------|---------|--------|
| Reflog (+ restore) | DEMOTE | спасение коммитов — синьор, пару раз в месяц |
| Worktrees | DEMOTE | power-фича, единицы пользуются |
| Interactive rebase | KEEP в ПКМ коммита (там и место), но это Tier-2 по сути |
| .gitignore editor | DEMOTE | используется в основном при init репо |
| SSH keys | DEMOTE/в Settings | одноразовая настройка, не ежедневное |

### Tier 3 — Балласт (CUT или за флаг «экспериментальное»)
Честно: миддл/синьор этим в GUI-клиенте не пользуются. Добавлено «для галочки».

| Фича | Вердикт | Почему |
|------|---------|--------|
| **AI-хелперы кроме commit message** | CUT / флаг | explain commit, smart stash naming, reflog explainer, conflict helper, semantic search (MVP без embeddings) — гиммики. Синьор читает diff сам, имя стэша пишет за 2 сек. Раздувают AI Settings (6 табов!) и бандл |
| **Статистика репозитория** (heatmap, insights, top-contributors) | CUT / отдельная необязательная вкладка | vanity-метрики для менеджера, не для работы. Разработчик не открывает heatmap чтобы закоммитить |
| **Git Bisect** | CUT или DEMOTE | реально нужен редко, и тогда чаще из CLI (`git bisect run`). В GUI — почти никогда |
| **Git Hooks (вкл/выкл переименованием)** | CUT или DEMOTE | хуки ставят через husky/конфиг, а не тумблером в GUI |
| **Git LFS manager** | DEMOTE + контекстно | полезно ТОЛЬКО в LFS-репо. Показывать пункт, только если репо реально использует LFS, иначе — шум |
| Заметки по веткам (branch notes) | CUT | локальные заметки на ветку — почти никто не ведёт |

### PASSIVE-KEEP (дёшево, не мусорит — оставить)
Signed-commit бейджи, long-path auto-suggest (Win), стрелки ↑/↓ в графе, Markdown-preview в diff, ПКМ «Копировать» в diff, темы, i18n, pin/solo/hide графа (solo/hide реально полезны на больших репо), индикатор Git activity log, подсветка выбранной ветки.

## 3. Предлагаемая структура меню «Repository»

**Было (17 пунктов в один уровень):**
Refresh · Fetch · Pull · Push · Stash · Stash Pop · Reflog · Bisect · Hooks · Worktrees · LFS · .gitignore · Statistics · Open in Explorer · Open in Terminal · Repository Settings · AI Settings

**Стало (предложение):**
```
Repository
├─ Refresh                F5
├──────────
├─ Fetch / Pull / Push
├─ Stash / Stash Pop
├──────────
├─ Open in Explorer / Terminal
├─ Repository Settings…   (user, credentials)
├─ AI Settings…
└─ Ещё (Advanced) ▶
     ├─ Reflog…
     ├─ Worktrees…
     ├─ .gitignore…
     ├─ Git LFS…          (только если репо с LFS)
     ├─ Git Hooks…
     ├─ Bisect…
     └─ Statistics…
```
Statistics уходит в «Ещё» (не вырезаем). SSH keys переезжает в Repository Settings.

### 3.1. Проработка задачи «меню» (что конкретно делать)

**Главное ограничение:** верхний `MenuBar` (`src/renderer/src/ui/MenuBar.tsx`) сейчас НЕ поддерживает вложенные подменю — `MenuItem` это плоский `{ label, accelerator, action, type:'separator', disabled }`. Чтобы сделать «Ещё ▶», нужно сначала научить `MenuBar` флай-аут подменю (в контекстном меню `SgContextMenu` это уже есть — можно подсмотреть логику `SubmenuItem`).

**Шаги:**

1. **Расширить `MenuBar`:**
   - В `MenuItem` добавить `submenu?: MenuItem[]`.
   - В рендере дропдауна: если у пункта есть `submenu` — рендерить его как раскрывающийся вправо флай-аут (hover/click), с позиционированием и flip у края экрана (по образцу `SgContextMenu.SubmenuItem`).
   - Закрытие родительского меню после клика по пункту подменю.

2. **Перестроить меню Repository в `TitleBar.tsx`** (массив `menus`, группа `loc.menu.repository`):
   - Первый уровень: Refresh · (—) · Fetch · Pull · Push · (—) · Stash · Stash Pop · (—) · Open in Explorer · Open in Terminal · (—) · Repository Settings… · AI Settings… · (—) · **Ещё ▶**.
   - В подменю «Ещё»: Reflog · Worktrees · .gitignore · (Git LFS — см. п.4) · Git Hooks · Bisect · Statistics.
   - Убрать из первого уровня: reflog, bisect, hooks, worktrees, lfs, gitignore, statistics.

3. **i18n:** добавить ключ `loc.menu.more` (RU «Ещё», EN «More»). Проверить тест полноты i18n (en/ru синхронны).

4. **LFS — контекстный пункт:** показывать «Git LFS…» в подменю, только если в активном репо реально используется LFS. Нужен флаг в state (например `state.usesLfs`) — проверить, отдаёт ли backend такой признак (`LfsManager`); если нет — добавить лёгкую проверку (`.gitattributes` содержит `filter=lfs` или `git lfs ls-files` непустой) и прокинуть в state. Если флаг false — пункт не рендерим.

5. **SSH keys:** убрать пункт из меню File (`TitleBar.tsx`), перенести точкой входа в `RepoSettingsDialog` (там уже есть `onOpenSshKeys`). Сам пункт `sshKeys` в `useMenuActions` оставить — его теперь дёргает кнопка в настройках.

6. **Не трогаем:** горячие клавиши Fetch/Pull/Push/Stash остаются (они и так на первом уровне). Reflog/Bisect и т.п. без акселераторов — ок.

**Файлы:** `ui/MenuBar.tsx`, `ui/MenuBar.module.css` (стили флай-аута), `features/titlebar/TitleBar.tsx`, `i18n/en.ts` + `ru.ts`, возможно `types.ts` + state-слой (флаг LFS).

**Риск/проверка:** клавиатурная навигация и закрытие по клику вне меню не должны сломаться; проверить, что подменю не уезжает за край окна.

## 5. Честный вывод

Реальные отличия GitBor от Fork/GitKraken для нашей (рус/корп) аудитории:
**встроенный git, AI commit (локальный/корпоративный), слой защиты данных, изоляция multi-repo, управление credentials.** Это — ценность.

Bisect / Hooks / LFS-менеджер / Статистика / AI-хелперы — это «фич-чеклист», который не используют, но который раздувает меню, бандл (уже упёрлись в bundle-gate) и когнитивную нагрузку. Резать не страшно — функции git никуда не денутся (CLI на месте), уходит только GUI-обёртка, которой никто не пользуется.

Меньше пунктов → понятнее человеку → быстрее онбординг миддла. Это и есть «делать для людей».

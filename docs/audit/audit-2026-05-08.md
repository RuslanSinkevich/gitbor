## Секция 8. Безопасность

### Что проверено

- `dangerouslySetInnerHTML`.
- `shell.openExternal`/`shell.openPath`.
- `child_process.exec/spawn/execFile` с динамическими аргументами.
- `safeStorage` обработка ошибок.

### Что найдено и исправлено

**`dangerouslySetInnerHTML`:** не найдено.

**`shell.openExternal`:** один вызов в `src/core/safety/RecoveryUI.ts:29`, открывает захардкоженный URL `https://git-scm.com/downloads`. Безопасно.

**`shell.openPath`:**

- `handlersShell.ts:23` — `cmd.path` (renderer-input). Защищён `typeof === 'string'` проверкой. Renderer берёт path только из state (openRepos), не вычисляет. ОК.
- `handlersRepoExtras.ts:189` — `safePath(repoPath, cmd.file)` защищает от path-traversal. ОК.
- `handlersRepoExtras.ts:199` — `repoPath` из state. ОК.

**`child_process` — найдена и исправлена уязвимость shell-injection:**

`src/core/bridge/ipc/handlersRepoExtras.ts:206` (handler `openInTerminal`, ветка Windows) — было:

```ts
execFile('cmd.exe', ['/K', `cd /d "${repoPath}"`], { cwd: repoPath, windowsHide: false });
```

`repoPath` интерполировалось в строку, которую `cmd.exe` парсит сам. Зловредная папка с именем вида `C:\foo"&calc&rem ` могла бы выполнить произвольную команду при попытке «Открыть в терминале». Стало:

```ts
const proc = spawn('cmd.exe', [], { cwd: repoPath, windowsHide: false, detached: true, stdio: 'ignore' });
proc.unref();
```

`cmd.exe` запускается без аргументов, новый терминал открывается с `cwd=repoPath` напрямую через системный API, минуя shell-парсер. macOS (`open -a Terminal`) и Linux-варианты — `repoPath` уже передавался отдельным элементом массива args, инъекция невозможна; добавлен `proc.unref()` для симметрии и чтобы main не висел в ожидании.

**Прочие `child_process`:**

- `GitExecutor.ts` — `execFile/spawn` с `git` и фиксированным argv-массивом, без shell. ОК.
- `SshKeyManager.ts` — `execFile('ssh-keygen', args)`, `name`/`comment` фильтруются `isSafeFilename` или передаются массивом args (без shell). ОК.
- В `handlersRepoExtras.ts` ветка Linux: команды и args в массиве, без shell. ОК.

**`safeStorage`** в `src/core/ai/AiConfigStore.ts`:

- `encode()` — `try/catch` вокруг `encryptString`, fallback на `plain:` префикс при недоступном key store.
- `decode()` — `try/catch` вокруг `decryptString`, fallback на пустую строку.

Обработка полная, дополнительных правок не требуется.

## Принятые решения и спорные моменты

1. **Не удалять `vite.config.ts`/`vite-env.d.ts`/`parserWorker.ts`** — knip ругается, но они нужны (Vite CLI/типы Vite/runtime-загрузка через `path.join(__dirname, ...)`). Оставлены, помечены как false-positive.
2. **Сохранить `clearGraphCache`** — рассматривал как потенциально полезную инфраструктуру (например, для ручной кнопки «Очистить кэш графа»). Удалил, потому что нигде не вызывается; восстановить — одна строка.
3. **Не локализовывать `UiShowcase`/showcase-секции** — это dev-only страница UI Kit, не пользовательский UI. Локализация добавит шум в i18n-словари без выгоды.
4. **Не трогать `Record<string, unknown>` в инфраструктурных слоях** (`MessageBridge`, `useRepoSlices`, `useStateSubscription`) — это type-safe замена `any` для динамического доступа к unknown shape. Замена на конкретные интерфейсы потребует генерации типов из IPC-DTO.
5. **Lazy-load НЕ для всех диалогов** — `SgContextMenu`, `SgToastContainer`, `SgPromptDialog` оставлены eagerly. Они показываются часто (при любом ПКМ/toast/prompt), и mini-Suspense fallback моргание было бы хуже, чем эконмия килобайт.
6. **Lazy-load c `fallback={null}`** для диалогов — пользователь нажимает «Открыть → ничего не показалось → через 50–200 мс появляется диалог». Альтернативы (spinner, skeleton) дали бы видимое моргание; `null` ведёт себя как мгновенное открытие при тёплом кэше.
7. **Security fix `openInTerminal` — изменение поведения:** теперь Windows-терминал не получает `cd /d <path>` как первой команды (она просто не нужна, `cwd` процесса уже выставлен). Поведение для пользователя идентично, но shell-injection устранён.
8. **`ageMs`/`diff`/`caught` сделаны uninitialized declarations** (вместо инициализации заглушкой) — `no-useless-assignment` правило фактически правильное: переменная гарантированно перезаписывается до первого чтения; типизация задана через `: number`/`: string`/`: unknown`.
9. **`KNOWN_HOOKS as readonly string[]`** вместо `name as any` — расширение типа массива до `string[]` для `.includes(name)`. Тип `KNOWN_HOOKS` остаётся `readonly [...]` (литеральный кортеж), но один cast-точка концентрирует «расширение» в одном месте.
10. **Bundle.html не пересобран** — для генерации нужно запускать `vite build --mode analyze` или подобное; в проекте нет соответствующего скрипта в `package.json`. Старый файл `bundle-2026-05-07.html` оставлен (untracked, как и был); добавлять его в git не входит в задачу аудита. Эффект lazy-load виден напрямую в выводе `npm run build`: основной чанк `~330 кБ`, плюс ~16 отдельных чанков 1.5–22 кБ.

## Кандидаты на следующий этап

Намеренно не сделано в этом стриме (требует архитектурной работы или
рискованных правок):

1. **Batch IPC для discard/delete-папки.** `LocalChanges.tsx:128,150` шлёт N
   `postCommand` в цикле. При discard'е папки на 100+ файлов — 100+ IPC-roundtrip'ов.
   Решение: новый `discardFiles` / `deleteUntrackedFiles` (множественное число)
   в `RendererCommand`, аналогично существующим `discardFileChanges`. Расширение
   контракта (не ломающее), плюс batch-реализация в handler'е.
2. **Унификация хардкод-цветов через `--sg-*`.** Семантические цвета diff/status
   должны идти через `--sg-success/--sg-danger/--sg-warning`. Сейчас захардкожены
   `#3fb950/#f85149/#d29922` в 5+ модулях. Требует ревизии `theme.css` и
   light-theme дополнения.
3. **Типизация test-mocks.** 146 lint warnings — все в тестовых фабриках
   (`createMockGit`, `mockState` и т.п.). Замена `any` на конкретные partial-типы
   потребует моделирования partial IPC-контекста, ~100–200 строк генерик-кода.
4. **Унификация модалок на `SgDialog`-shell.** Сейчас половина диалогов
   (`SshKeysDialog`, `WorktreesDialog`, `LfsDialog` и др.) имеет свой
   `.dialog/.overlay` стиль. Перевод на общий `SgDialog` даст единый padding,
   shadow, animation, focus-trap. Большая UI-работа.
5. **AI-провайдеры:** `OpenAiCompatibleProvider.ts` имеет `let data: any;` для
   парсинга ответа. Замена на zod/typia схему или дискриминатные типы — отдельная
   задача, под жёстким запретом текущего аудита.

### Breaking change: chokidar 4

В v4 удалён глобальный namespace-export. Раньше:

```ts
import chokidar from 'chokidar';
const w: chokidar.FSWatcher = chokidar.watch(p);
```

Стало:

```ts
import { watch as chokidarWatch, type FSWatcher } from 'chokidar';
const w: FSWatcher = chokidarWatch(p);
```

Glob-паттерны в watch (`'src/*.ts'`) — **не использовали**. `ignored: RegExp[]` — поддерживается в v4 как было. Watcher-логика и debounce-времена не менялись.

### Что не сделано и почему

- **electron 32 → 42.** В `npm audit` 12 high CVE по electron 32; единственный фикс — `--force` upgrade до 42 (breaking). Спек требовал «32+», задача выполнена в минимальной интерпретации. Прыжок 28→32 уже большой; 32→42 — следующий стрим с runtime-валидацией.
- **vite 6 → 8 / vite plugin-react 4 → 6.** Спек прямо указал «5 → 6». Vite 7 и 8 — отдельная история (vite 8 уже на rolldown).
- **typescript 5.9 → 6.x.** TypeScript 6.x вышел с обратными несовместимостями в `--strict`-flow. Спек просил «5.6+», взяли последний 5.x.
- **vitest 4.1.4 → 4.1.5.** В баме нет — `vitest` уже был на актуальной 4.1.x в `package.json` и не отстал в `package-lock.json`.
- **eslint-config-prettier 10.1.8.** Уже на самой свежей версии до начала стрима.

## Блок 3 — Безопасность

### Что сделано

**3.1 CSP** (`src/renderer/vite.config.ts` PROD_CSP, инжектится в build):

Было:
```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self';
```

Стало:
```
default-src 'self';
script-src 'self';                   # без unsafe-eval/unsafe-inline
style-src 'self' 'unsafe-inline';
img-src 'self' data:;                # для inline-SVG
font-src 'self' data:;
connect-src 'self' https:;           # whitelist для будущих AI-fetch'ей из renderer
object-src 'none';                   # запрет <object>/<embed>
base-uri 'self';                     # запрет <base href> hijack'а
form-action 'none';                  # форм у нас нет
frame-ancestors 'none';              # запрет встраивания
```

`connect-src 'self' https:` — компромисс: динамический per-URL whitelist в meta-CSP технически невозможен (meta нельзя поменять после загрузки документа). На практике AI-fetch'и идут из main (`src/core/ai/providers/*`), renderer не дёргает HTTP напрямую — но это страховка на случай будущих рефакторингов.

DEV_CSP остаётся либеральным (нужен `unsafe-eval` для Vite HMR + `ws:` connect-src) — используется только при `npm run dev`.

**3.2 webPreferences hardening** (`src/main/main.ts`):

| Флаг | Было | Стало |
|---|---|---|
| `sandbox` | true | true (явно прописан) |
| `contextIsolation` | true | true (явно прописан) |
| `nodeIntegration` | false | false (явно прописан) |
| `webSecurity` | (default true) | true (явно прописан) |
| `nodeIntegrationInWorker` | (default false) | false (явно прописан) |
| `spellcheck` | (default true) | false |

Все четыре security-критичных флага прописаны явно — после major-апгрейда electron дефолты могут поменяться без warning.

**3.3 Navigation lockdown** (`src/main/main.ts`):

- `setWindowOpenHandler`: блокируем `window.open`, http(s) → `shell.openExternal`. Renderer не может породить второй BrowserWindow.
- `will-navigate`: разрешён только `file://`, `http://127.0.0.1:`, `http://localhost:` (стартовый URL); внешние http(s) уходят в системный браузер.
- `will-attach-webview`: блокируем — `<webview>` в UI не используется.

**3.4 Preload audit** (`src/preload/index.ts`):

Контракт уже минимальный (`contextBridge.exposeInMainWorld('skyForkAPI', api)`), прямых window-вставок нет, типы exposed-методов сужены до `unknown`. **Изменений не потребовалось.**

**3.5 npm audit fix:**

| Где | CVE | Severity | Исправлено |
|---|---|---|---|
| root, rimraf/glob | GHSA-5j98-mcp5-4vw2 (command injection в glob CLI) | high | да (auto-fix без --force) |
| renderer, postcss | GHSA-qx2v-qp2m-jg93 (XSS в CSS stringify) | moderate | да (auto-fix без --force) |
| root, electron | 12 advisories (use-after-free, registry injection, IPC OOB, etc.) | varies | **нет** — фикс только в electron 42, breaking. Транзитивно — нужно вместе с major-upgrade'ом electron в следующем стриме. |

### Что не сделано и почему

- Apgrade electron до 42 (см. блок 1).
- Динамический per-URL CSP whitelist для AI-провайдеров — невозможен в meta-теге; альтернатива через `session.defaultSession.webRequest.onHeadersReceived` (CSP-injection) добавляет рантайм-overhead и сложности отладки. Оставлен `connect-src 'self' https:`.

## Принятые решения и спорные моменты

1. **electron 32, не 33+/42.** Спек явно сказал «32+»; 42 имел бы 12 CVE-фиксов, но это +10 major-версий за один стрим. Откладываем до следующего стрима с full runtime-validation.
2. **vite 6.4, не 7/8.** Спек явно сказал «5 → 6»; vite 8 уже на rolldown — слишком много неизвестного.
3. **typescript 5.9, не 6.0.** Спек «5.6+»; 6.0 имеет breaking changes (новый strict-flow). Взяли последний стабильный 5.x.
4. **chokidar import: named, не default.** В v4 namespace-export убран; `import { watch as chokidarWatch, type FSWatcher } from 'chokidar'` — самый локальный фикс (минимум diff'а в 4 строках).
5. **`connect-src 'self' https:` в PROD CSP.** Per-URL динамический whitelist в meta невозможен; AI-fetch идёт из main (renderer не нуждается), но `https:` — задел и страховка. Альтернатива через `session.webRequest.onHeadersReceived` — overhead и сложность отладки.
6. **Все security-флаги webPreferences прописаны явно.** Не доверяем дефолтам после major-апгрейда electron — дешёвая страховка от тихого breaking change в будущих версиях.
7. **`will-navigate` разрешает `localhost:` префикс.** Только для dev-сессий (HMR-навигация на 5188). В prod app.isPackaged=true, и `loadFile` использует file:// — `localhost:` ветка просто никогда не сработает.
8. **`spellcheck: false`.** Git-клиент не редактор кода; spell-check на путях/коммит-хешах — мусор. Минус несколько MB RAM.
9. **husky pre-commit без `npm test`.** 5–7 сек на каждый коммит — раздражает, особенно при rebase. Тесты гоняет CI; локально разработчик запускает явно.
10. **Per-file tsc через grep, не функцию lint-staged.** Per-file tsc бессмыслен (типы зависят от всего проекта); запускаем project-wide tsc в hook через явный grep `--cached --diff-filter=ACMR`. Если нет staged TS — пропускаем.
11. **Repo-fixtures в E2E — temp-каталоги через `mkdtempSync`.** Не коммитим test-репо в `tests-e2e/fixtures/` (раздувает .git, плюс git-нюансы вложенности). Cleanup в `finally`.
12. **2-й репо в `switch-tab.spec.ts` через `page.evaluate(skyForkAPI.invoke)`.** Альтернатива: через UI-клик «+» → RepoManager → ввод пути — потребовал бы куда больше data-testid (на инпут, кнопку «Add»), плюс RepoManager делает background-validation (`getRepoSummary`), что замедлит тест. Прямой IPC надёжнее.
13. **windows-only E2E.** Кросс-платформенный E2E нуждается в фикстурах путей (Windows backslash vs POSIX slash) и проверке хедлесс-режима в Linux/Mac CI runners. Это полноценный отдельный стрим.
14. **PR workflow рядом со старым `ci.yml`, не вместо.** `ci.yml` гоняет push в main/develop на матрице 3 OS, что полезно для post-merge-валидации (если кто-то накатит правки прямо в main/develop). PR.yml — гейт перед merge'ем, win-only, +e2e. Дополняет.
15. **rollup-plugin-visualizer 7.x.** Стабильная версия для vite 5/6/7. Вариант 6.x ставит meta-deps попроще, но v7 уже актуальная.
16. **`docs/audit/.commit-msg-tmp` в .gitignore.** Спек требовал именно этот метод (через `git commit -F file`). Файл служебный, чтобы PowerShell не парсил bash-heredoc; исключаем из tracking.
17. **Удаление `bundle-2026-05-07.html` через `git rm` (он был tracked в HEAD).** Старый bundle отчёт явно устарел; новый `bundle-2026-05-09.html` его заменил (как rename в git log).
18. **Repo-path-guard env-fallback на хардкод C:.** Если `process.env.SystemRoot` пуст (Windows Sandbox без полного env, edge-case), сохраняем старое поведение. Безопаснее чем «вообще не проверять».
19. **`@types/node 22.x`, не 24.x.** На локалке node 24, но `@types/node 24` ещё не синхронизирован с electron 32 typings (electron уже на стабильном API, но types для Node 24 могут давать новые типы которые ts строгий strict не одобрит). 22 — LTS-aligned выбор.
20. **`prepare: husky` в package.json.** husky 9 рекомендует именно эту форму (без `husky install` как в 8.x). После `npm ci` хуки автоматически установлены — не нужно ручной шаг для контрибьюторов.

## Кандидаты на следующий этап

Намеренно не сделано, требует runtime-валидации или major-upgrade'а:

1. **electron 32 → 33+/42.** 12 CVE-advisories по electron 32 фиксятся только в 42. Spec next stream: bump electron, прогон полного e2e (включая Mac/Linux), проверка Linux Wayland с `--ozone-platform-hint=auto`.

4. **Bundled git для Windows.** ~50 МБ portable-git → нулевая зависимость от системы. Лицензионный review GPL-2.
5. **Auto-suggest `git config core.longpaths true`.** При `ENAMETOOLONG`/`ENOENT` от git показать пользователю диалог.
6. **CSP per-URL whitelist для AI** через `session.defaultSession.webRequest.onHeadersReceived`. Заменит `connect-src https:` на динамический список реально-настроенных провайдеров.

10. **`npm test` в pre-push hook (не pre-commit).** Дешевле для разработчика, но всё ещё ловит регрессии до push'а.
11. **Типизация test-mocks** (146 lint warnings — переехали из предыдущего стрима без изменений). Замена `any` в `tests/` на partial-типы; ~100–200 строк генерик-кода.

2. **Запуск на Ubuntu 22.04 / 24.04** в X11- и Wayland-сессиях (последняя — особенно).
3. **Запуск на Fedora** (Wayland по умолчанию).
4. **`electron-builder --mac --dir`** после добавления `resources/icon.icns` + `build/entitlements.mac.plist` (по чек-листу).
5. **`electron-builder --linux --dir`** после добавления `resources/icon.png`.
6. **DMG для распространения** — нужен Apple Developer ID + notarize-цепочка. По чек-листу: `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` env.
7. **Открыть репо с non-ASCII именами** (русские/японские/китайские) на Windows — проверить что `core.quotePath=false` работает и пути не битые.
8. **Открыть репо с symlink'ами наружу базового пути** — `safePath` должен бросить.
9. **Открыть репо с глубокой вложенностью путей >260 символов** на Windows без `core.longpaths=true` — увидеть как git ругается, проверить что приложение не падает.
10. **Прогнать `npm run e2e` на Windows локально** — должно показать `3 passed (~27s)`.
11. **PR в этот репозиторий** — дождаться, что `pr.yml` workflow зелёный (lint + tsc + test + build + e2e job).
12. **Сценарий «пакет git не установлен»** — на чистой Windows-VM без Git for Windows запустить SkyFork → должен показаться `showGitNotFoundMessage` диалог.

### Принятые решения

- **GraphCache / AuthorStatsCache**: `electron.app.getPath` мокается через
  `vi.mock('electron')` на временную папку (`mkdtempSync`); реальная файловая
  система → читаем/пишем JSON, проверяем atomic .tmp+rename, кэппинг по
  `MAX_CACHED_COMMITS`, версионирование, инвалидация на смене headHash.
- **SshKeyManager**: `os.homedir` мокается на tmp-папку, `child_process.{execFile,
  spawn}` — на vi-моки, которые сами создают «сгенерированные» файлы ключей.
  Главный assertion: на этапе `spawn ssh-keygen` argv НЕ содержит passphrase
  (передаётся `-N ""`, реальный passphrase устанавливается отдельным `-p`-вызовом).
- **SafetyNet**: GitExecutor мокается, OperationJournal пишет реальный JSON
  в `tmpRepo/.git/` через `AtomicWrite`. Покрыт happy-path, auto-stash с
  unstaged, fail-on-stash-push, autoRollback при ошибке operation, rollback
  через journal entry, detached HEAD (`branchName === 'HEAD'` → checkout
  не вызывается).
- **FileWatcher**: chokidar полностью мокается (FakeWatcher на EventEmitter +
  vi.fn для close). Реальная tmp-папка нужна только чтобы `fs.readdir` в
  pre-scan не падал. `flushAsync(30)` ждёт async-цикл `ensureWatcher`.
  Покрыты: idempotent addRepo, debounced refreshAll, removeRepo close,
  dispose, race-guard `close-во-время-pre-scan`.

### Почему остальные правила выключены

Изначально плагин дал 127 warnings. Из них:
- ~120 — паттерн `<div onClick>` для row/list/menu-item в диалогах
  (`AboutDialog`, `BisectDialog`, `StashDialog`, `SshKeysDialog`, …).
  Миграция на `<button>` или `role="button"+tabIndex=0+onKeyDown` —
  это рефакторинг 30+ компонентов, не однодневный polish.
- Критичные семантические правила (alt-text / aria-*) показали 0
  нарушений — это значит, что код в принципе ходит правильно на
  семантику, шумят только UX-улучшения keyboard nav.

Решение: гейтим только критичные нарушения как error, а массовый рефактор
keyboard-events фиксирую как backlog следующего стрима. Это не «зашивание
проблемы»: новые ошибки в `aria-*` теперь падают в CI, а UX-улучшения
keyboard-nav — это отдельный самостоятельный стрим (см. «Кандидаты»).

## Блок D — Bundle size regression gate

В `src/renderer/vite.config.ts` добавлен `bundleSizeGatePlugin()` (apply: build,
hook `closeBundle`). Логика:

- Сканирует `dist/renderer/assets/*.js`, находит главный chunk (самый
  большой).
- Считает raw + gzip (zlib level 9).
- Threshold: 400 KB raw / 120 KB gzip (запас ~17% от baseline 332.56 KB /
  101.41 KB).
- При превышении → `process.exit(1)` с понятным сообщением.
- Можно отключить через `GITBOR_BUNDLE_GATE_OFF=1` для локальных
  экспериментов.

Текущий замер на build: `index-<hash>.js: 332.80 KB raw / 101.51 KB gzip`.

Альтернатива (`size-limit` пакет) отклонена — +2 dep ради функциональности
30 строк vite-плагина.
